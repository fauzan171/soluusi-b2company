# T4.3 — Unify session state machine

## Goal
Single source of truth for session status transitions.

## Evidence
Session state mutations in 3 places:
- `BookingService::book/cancel/reschedule`
- `ChatController::consultantStart/consultantEnd/employeeEnd`
- `Klinik\SessionController::checkIn/markDone/verify`

## Perubahan

1. Create `app/Services/SessionStateMachine.php`:
   - `book(Schedule $slot, $row, array $data)` — create session
   - `cancel($session, string $reason)` — cancel + quota restore logic
   - `reschedule($session, Schedule $newSlot)` — cancel + book
   - `checkIn($session)` — mark checked_in_at
   - `start($session)` — start session (consultant)
   - `end($session)` — mark done + completed_at
   - `markDone($session)` — klinik flow done
   - `verify($session)` — ops verify

2. Each method validates current state before transition.

3. Refactor callers to use `SessionStateMachine`:
   - `BookingService` → delegate to state machine
   - `ChatController` → call state machine
   - `Klinik\SessionController` → call state machine

4. Add `reschedule_count` tracking (prep for T6.2 MAX_SCHEDULES_PER_SESSION).

## Verify

- [ ] Test: invalid state transition (e.g., end before start) → 422
