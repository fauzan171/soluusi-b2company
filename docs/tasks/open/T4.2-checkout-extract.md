# T4.2 — Extract CheckoutFlow service from CheckoutController

## Goal
Split the 629-line `CheckoutController` god class into a proper service layer.

## Evidence
`app/Http/Controllers/CheckoutController.php` — 629 lines doing payment orchestration, voucher math, session reservation, dummy payment, view-state mapping, consultant queries.

## Perubahan

1. Create `app/Services/Klinik/CheckoutFlow.php`:
   - `startPayment(array $data, CheckoutLink $link)` — main payment flow
   - `startDummyPayment(...)` — dummy payment for local dev
   - `reserveSession(...)` — atomic session reservation with lockForUpdate
   - `calculateVoucherDiscount(...)` — voucher math

2. Create `app/Support/Checkout/CustomerDashboardState.php`:
   - Extract the 90-line state-machine-in-array from `customerDashboardState`

3. Refactor `CheckoutController` to:
   - Keep only HTTP verbs (clinic, clinicPay, show, pay, dummyPayment, status, confirmDone)
   - Delegate all business logic to `CheckoutFlow`
   - Keep validation in Form Requests

4. Ensure `reserveSession` uses `lockForUpdate` and is race-safe (from security audit finding).
