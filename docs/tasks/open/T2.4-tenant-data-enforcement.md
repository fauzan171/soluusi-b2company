# T2.4 — Tenant enforcement di layer data

## Goal
Kolom `tenant_id` saja bukan isolasi. Tambah enforcement di model level agar query tanpa tenant filter otomatis di-scope atau ditolak.

## Evidence
- Model `PerusahaanSession`, `PerusahaanEmployee`, `SekolahSession`, `SekolahStudent` punya `perusahaan_id`/`sekolah_id` tapi tidak ada global scope.
- Query seperti `PerusahaanSession::all()` akan return semua data lintas tenant.

## Perubahan

### Opsi A: Global Scope (recommended untuk MVP)
Buat `app/Models/Scopes/TenantScope.php`:

```php
class TenantScope implements Scope
{
    public function apply(Builder $builder, Model $model)
    {
        if ($tenantId = $this->getCurrentTenantId()) {
            $builder->where($model->getTable().'.'.$this->getTenantColumn(), $tenantId);
        }
    }
}
```

Apply di model tenant-scoped via `booted()`:
```php
protected static function booted()
{
    static::addGlobalScope(new TenantScope('perusahaan'));
}
```

### Opsi B: Base Model dengan enforcement
Extend `App\Models\Model` (yang sudah ada) untuk force tenant check di `newQuery()`.

### Pilihan: Opsi A (Global Scope)

Model yang perlu scope:
- `PerusahaanSession`, `PerusahaanEmployee`, `PerusahaanAssessment`
- `SekolahSession`, `SekolahStudent`, `SekolahAssessment`
- `CheckoutLink` (via `klinik_id`)
- `Schedule` (via `klinik_id` atau `perusahaan_id` atau `sekolah_id`)
