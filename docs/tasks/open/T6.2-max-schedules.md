# T6.2 — MAX_SCHEDULES_PER_SESSION enforcement

## ADR
Lihat `docs/adr/001-max-schedules-per-session.md` — **total 3 jadwal** (1 awal + 2 reschedule).

## Perubahan

1. Add to `config/session.php`:
```php
'max_schedules_per_session' => env('MAX_SCHEDULES_PER_SESSION', 3),
```

2. Add migration for `schedule_version` on `consultation_sessions`, `perusahaan_sessions`, `sekolah_sessions`:
   - Integer, default 1 (jadwal awal = versi 1)

3. Update `SessionStateMachine::reschedule`:
   - Check `$session->schedule_version >= config('session.max_schedules_per_session')`
   - Abort 422: "Maksimal perubahan jadwal tercapai (maks 3)"
   - Increment `schedule_version` on successful reschedule

4. Optional: add `schedule_history` JSON column for audit trail

## Verify
- [ ] `php artisan tinker --execute="config('session.max_schedules_per_session')"` returns 3
- [ ] Test: jadwal awal + 2 reschedule = OK, reschedule ke-3 (total 4) ditolak 422
- [ ] Test: `schedule_version` increments correctly

## Out of scope
- UI to show remaining schedule changes
- Admin reset capability
